01 · Pendahuluan

Latar Belakang

Di era Industri 4.0, banyak industri masih mengandalkan monitoring mesin secara manual. Keterlambatan mendeteksi kondisi abnormal dapat berujung pada kerusakan komponen, terhentinya produksi, hingga risiko keselamatan kerja.

IoT memungkinkan sensor terhubung ke internet dan dipantau dari jarak jauh secara real-time — sehingga keputusan dapat diambil lebih cepat dan tepat.

Monitoring manual

Butuh kehadiran operator secara fisik — lambat merespons anomali.

Tanpa data historis

Sulit melakukan analisis tren & mempersiapkan predictive maintenance.

Respons lambat

Kondisi kritis seperti suhu berlebih perlu dihentikan dalam hitungan milidetik.

03 · Desain Sistem

Komponen Hardware

Satu mikrokontroler, tiga sensor, satu aktuator — bekerja sebagai satu kesatuan.

DS18B20

Sensor Suhu

Digital one-wire, rentang −55°C s.d. +125°C, presisi ±0.5°C.

SW-420

Sensor Getaran

Output digital HIGH saat getaran melebihi threshold mekanis.

KY-037

Sensor Suara

Deteksi noise lingkungan, dipakai mode digital untuk efisiensi GPIO.

RELAY

Relay Module

Aktuator pemutus listrik, konfigurasi active-low.

ESP32 — mikrokontroler 32-bit dual-core dengan WiFi & Bluetooth bawaan, berperan sebagai gateway IoT yang mengumpulkan data sensor dan menjalankan logic kontrol relay secara lokal.

03 · Desain Sistem

Protokol & Format Data

Struktur topic MQTT yang hirarkis & mudah diperluas untuk multiple unit mesin.

PUBLISHmesin/unit1/dataESP32 → broker
SUBSCRIBEmesin/unit1/cmddashboard → ESP32

Cukup tambah mesin/unit2/data untuk skala lebih besar — tanpa mengubah arsitektur.

payload.json — mesin/unit1/data
{
  "suhu": 45.5,        // float °C
  "getaran": 0,        // 0/1
  "suara": 1,          // 0/1
  "relay": 1,          // 1=ON 0=OFF
  "status": "NORMAL",
  "pernahKritis": false
}
03 · Desain Sistem

Logic Kontrol — State Machine

Pendekatan fail-safe: sekali kritis terdeteksi, sistem terkunci hingga reset manual operator.

SUHU < 70°C
NORMAL
Relay ON · mesin berjalan normal
suhu ≥ 70°CpernahKritis = true
SUHU ≥ 70°C
KRITIS
Relay OFF · mesin dihentikan

LOCK aktif — relay tetap OFF meski suhu turun. Mesin hanya bisa menyala lagi setelah reset manual dari dashboard.

04 · Implementasi

Firmware ESP32

1

Koneksi WiFi & MQTT — konek ke HiveMQ via TLS port 8883 untuk keamanan komunikasi.

2

Pembacaan sensor — interval 3 detik, dikemas ke JSON lalu publish ke topic data.

3

Logic relay control — flag pernahKritis persistent, hanya di-reset via MQTT atau power cycle.

esp32_loop.ino
// baca sensor tiap 3 detik
float suhu = sensors.getTempC();

if (suhu >= 70.0) {
  pernahKritis = true;
  digitalWrite(RELAY, LOW);  // OFF
}
if (!pernahKritis)
  digitalWrite(RELAY, HIGH); // ON

client.publish("mesin/unit1/data", json);
04 · Implementasi

Node-RED Flow

Tiga flow utama mengubah data mentah menjadi monitoring, penyimpanan & alert.

Monitoring & Alert

Subscribe data, cek threshold suhu, tulis ke InfluxDB, kirim email alert hanya saat transisi state (anti email flooding).

Dashboard & Visualisasi

Grafik real-time suhu/getaran/suara, status setiap sensor, toggle relay manual & tombol reset lock.

Ekspor CSV

Unduh data 7 hari terakhir dari InfluxDB dalam format CSV untuk analisis offline & bahan machine learning.

05 · Hasil & Pembahasan

Tantangan & Lessons Learned

TANTANGAN

Stabilitas koneksi WiFi

ESP32 perlu tetap terhubung dalam jangka panjang.

SOLUSI

Reconnect logic robust

Monitoring signal strength + early warning saat sinyal melemah.

TANTANGAN

Noise pada sensor

Getaran & suara rawan false positive bila threshold tak terkalibrasi.

SOLUSI

Threshold adjustable

Dapat diatur via dashboard + moving average filter untuk smoothing.

TANTANGAN

Konsistensi data

Timestamp harus sinkron dengan kondisi real-time mesin.

SOLUSI

Sinkronisasi NTP

ESP32 sinkron ke server NTP global agar timestamp akurat.
